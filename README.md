## How I Approach Testing

1. **Understand the risk first** — test what would hurt users most, not just what's easy to automate
2. **Design before automating** — test cases, boundaries, and negative paths come before code
3. **Automate the regression, explore the unknown** — automation for repeatability, human curiosity for discovery
4. **Measure the suite** — pass rate, run time, flakiness. A test suite you can't trust is worse than none
5. **Document what I find** — a good bug report is a product: clear steps, expected vs. actual, evidence
