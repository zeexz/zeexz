<details>
<summary><b>🔍 My approach to testing</b></summary>

<br>

1. **Understand the risk first** — prioritise what would affect users most, not just what is easy to automate
2. **Design before automating** — test cases, boundaries, and negative paths come before code
3. **Automate the regression, explore the unknown** — automation for repeatability, exploratory testing for discovery
4. **Measure the suite** — pass rate, run time, and flakiness are tracked, not assumed
5. **Document findings clearly** — precise steps, expected vs. actual results, and supporting evidence

</details>
